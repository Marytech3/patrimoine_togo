Guide d’utilisation

Les étapes essentielles pour prendre en main la plateforme de gestion du patrimoine public.

Environnement de démonstrationLes biens et montants affichés sont fictifs. N’y saisissez aucune donnée personnelle, sensible ou réelle du patrimoine public.

1. Lancer la plateforme

Installez Docker Desktop avec Docker Compose v2, ouvrez un terminal à la racine du dépôt, puis lancez :

docker compose up --build

Une fois les services démarrés, ouvrez http://localhost:8081. Le prototype utilise le port 8081. Au premier lancement, le téléchargement des images et des dépendances peut prendre quelques minutes.

Pour arrêter la plateforme, utilisez Ctrl+C dans le terminal, puis exécutez docker compose down.

2. Consulter le tableau de bord

La vue d’ensemble présente le nombre de biens, leur valeur indicative, leur état et les dernières opérations. Les indicateurs sont calculés à partir des données de démonstration chargées dans PostgreSQL.

3. Rechercher un bien

Ouvrez Inventaire dans le menu latéral. Le champ de recherche accepte un nom, une référence, un ministère ou une localisation. Les filtres permettent de limiter la liste par état ou par catégorie.

4. Gérer les services de l’État

Dans Services de l’État, recherchez et créez des fiches pour les ministères et services : rattachement ministériel, région, préfecture, adresse, responsable et contact. Une fiche peut être modifiée, désactivée ou réactivée. Les services désactivés restent consultables pour préserver le contexte historique des biens.

5. Tracer un mouvement

Dans Mouvements, sélectionnez un bien, le type d’opération, une date et un motif. Pour une affectation ou un transfert, indiquez un service actif et une localisation de destination. L’application enregistre l’origine et la destination, puis actualise la fiche du bien. La maintenance, le retour de maintenance et la réforme actualisent son état sans le déplacer.

6. Ajouter un bien

Cliquez sur Ajouter un bien, puis renseignez le nom, la catégorie, le ministère ou service et la localisation. Ces champs sont obligatoires. Vous pouvez également indiquer l’état, la valeur estimée, la date d’acquisition, le type et une note.

Cliquez sur Enregistrer le bien. Lorsque l’API est connectée, le serveur génère une référence TG-… et enregistre la fiche dans PostgreSQL. Si l’API est indisponible, la plateforme indique que l’ajout est temporaire : il disparaîtra au rechargement de la page.

7. Exporter l’inventaire

Utilisez le bouton Exporter du tableau de bord ou Exporter CSV dans l’inventaire. Le fichier téléchargé est nommé inventaire-patrimoine-togo.csv, encodé en UTF-8 et séparé par des points-virgules.

8. Consulter les rapports

Dans Rapports, filtrez l’inventaire par dates d’acquisition, catégorie, état ou ministère. Les indicateurs et répartitions sont recalculés après application des filtres. L’export CSV contient les seules fiches du résultat courant.

9. Carte du territoire

La carte schématique regroupe les fiches selon les villes reconnues dans leur localisation. Sélectionnez une région pour consulter les biens correspondants. Les emplacements sont indicatifs : les fiches ne comportent pas de coordonnées GPS.

10. API de démonstration

Les routes suivantes sont accessibles depuis la machine qui exécute Docker :

  • État du service : GET /api/v1/health
  • Résumé : GET /api/v1/summary
  • Inventaire : GET /api/v1/assets?per_page=50
  • Services : GET/POST /api/v1/services et PUT/PATCH /api/v1/services/{id}
  • Mouvements : GET/POST /api/v1/movements
  • Rapport filtré : GET /api/v1/reports/summary avec les filtres from, to, category, status et ministry.

Préfixez chaque route par http://localhost:8081.

11. Réinitialiser les données

La commande docker compose down -v supprime le volume PostgreSQL et toutes les données locales du projet. Au prochain démarrage, la base et les exemples fictifs sont recréés.

Attention Cette commande efface définitivement les données enregistrées dans le volume local.

12. Dépannage

ProblèmeAction à essayer
La page ne s’ouvre pasVérifiez Docker Desktop, l’état des conteneurs avec docker compose ps et la disponibilité du port 8081.
Les indicateurs ne se chargent pasConsultez docker compose logs asset-api postgres, attendez le démarrage complet puis rechargez la page.
Erreur de connexion PostgreSQLConsultez les journaux Postgres et vérifiez la variable DB_PASSWORD.
Le port 8081 est occupéModifiez le port côté machine dans docker-compose.yml (par exemple 8082:80), redémarrez et ouvrez le nouveau port.

13. Limites du prototype

Cette version ne comprend pas encore d’authentification, de comptes personnels, de rôles de validation, de suppression logique, de sauvegarde ni de gestion documentaire. La carte est indicative et les données sont fictives ; ne les utilisez pas comme données officielles.
